EMORA LOCAL TTS UPGRADE — 2026-07-15
======================================

Scope
-----
Only the text-to-speech subsystem was changed. Conversation, memory, emotion,
STT, backend APIs, and the rest of the UI were not rewritten.

Model decision
--------------
Primary runtime: Qwen3-TTS 1.7B CustomVoice using MLX-Audio's 6-bit Apple
Silicon model: mlx-community/Qwen3-TTS-12Hz-1.7B-CustomVoice-6bit.

Why this model:
- Qwen3-TTS provides local expressive instruction control and streaming output,
  which directly covers emotional companion speech and low latency.
- MLX-Audio runs on Apple's MLX framework, so it is a better fit for the M5
  unified-memory machine than a CUDA-only deployment.
- The MLX upstream benchmark for this 6-bit CustomVoice configuration reports
  about 3.88 GB model memory and about 84.8 ms average time-to-first-audio for
  a short single request. That is a practical starting point within 16 GB,
  leaving room for FastAPI, the browser, and the conversation stack.
- Qwen3's official project documents CustomVoice instruction control and
  streaming. It is an open-source, local model download; cloud use is not
  required.

Why Kokoro was kept
-------------------
Kokoro is not the preferred engine any more, but it remains a local automatic
fallback. A missing MLX package, incomplete model download, or model-loading
failure no longer makes the companion silent. This is deliberately safer than
replacing the working path with a hard dependency on a multi-GB model.

Implemented changes
-------------------
1. Primary MLX/Qwen3 engine
   - `app/voice_manager.py` lazily loads and caches the configured Qwen3 MLX
     model once per process.
   - Existing voice IDs (`af_heart`, `af_bella`, `am_adam`, `am_michael`) and
     companion mappings remain accepted. Existing callers do not need to
     migrate their saved voice IDs. Character-specific Qwen speakers are
     resolved server-side from the character profile.
   - `TTS_ENGINE`, `TTS_QWEN_MODEL`, sample rate, stream interval, queue size,
     and dictionary path are configurable in `.env`.

2. True streaming and low-latency playback
   - `stream: true` now returns signed 16-bit PCM while the model produces
     chunks; it no longer builds an entire WAV file before sending a response.
   - Long replies are sentence-chunked (then safely word-chunked at 360
     characters) so the first complete thought starts before later text is
     synthesized, without splitting a word or unbounded generation request.
   - The browser reads the stream, schedules small Web Audio buffers ahead of
     the playhead, and begins playback on the first available audio chunk.
   - The prior API behavior remains: callers omitting `stream` receive the
     ordinary cached `audio/wav` response.

3. Stop speaking, queueing, and caching
   - Starting a new reply aborts the prior HTTP fetch, stops every scheduled
     Web Audio source, clears queued playback, and resets the avatar instantly.
   - The backend has a bounded hand-off queue and bounded pending-work
     semaphore; slow browser connections cannot accumulate unbounded chunks.
   - Neural model instances are cached in memory and completed WAV responses
     are cached on disk. Cache keys include engine, voice, style, speed, and
     normalized text so an emotional response cannot reuse the wrong audio.

4. Pronunciation preprocessing
   - `app/tts_text.py` expands abbreviations, all-caps acronyms, numbers,
     ISO/written dates, currencies, and AI/technical terms before synthesis.
   - Unknown all-caps acronyms use grapheme-to-phoneme letter-name expansion
     (for example, API becomes “A P I”) rather than being guessed as a word.
   - `models/voices/pronunciations.json` is the editable project dictionary;
     `spoken` controls the neural input and `phonemes` records the IPA/G2P
     pronunciation used for review/audit. Kokoro continues to use Misaki G2P
     over this normalized text.

5. Emotional styles
   - Eight explicit styles are implemented: calm, comforting, empathetic,
     excited, happy, sad, romantic, and professional.
   - A `speech.style` value wins when provided; otherwise compatible emotion
     labels from the existing brain payload choose a style. The style becomes a
     Qwen instruction, while speed/pause metadata remains honored.

6. Operational tools and documentation
   - `scripts/tts_setup.py --warmup` downloads/loads the configured model and
     creates one cached sample per companion.
   - `scripts/benchmark_tts.py` writes `TTS_BENCHMARK.json` with startup,
     first response latency, cached latency, peak RSS, WAV health, expected
     pronunciation cases, and a repeatable human listening rubric.
   - `VOICE_PIPELINE_README.md` now documents the MLX setup, PCM streaming
     contract, fallback, queue settings, custom dictionary, and benchmark.

Benchmark note
--------------
This checkout has no project `.venv` and the MLX/Qwen model is not installed or
downloaded here, so inventing device benchmark values would be misleading.
Run these exact target-machine commands after creating the Python 3.12 venv:

  python3 -m pip install -r requirements.txt
  python3 scripts/tts_setup.py --warmup
  python3 scripts/benchmark_tts.py

The produced JSON is the actual M5/16 GB benchmark. Subjective audio and
pronunciation quality are intentionally a scored listening rubric rather than
fabricated numeric claims.
